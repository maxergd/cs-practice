# Отчет по командам Git

## Различия между git log, git diff и git show:
* git log — показывает историю коммитов. С флагом --stat выводит краткую статистику измененных файлов и строк.
* git diff — показывает конкретную разницу в коде между коммитами или состояниями (в данном случае между HEAD~2 и HEAD).
* git show — показывает подробную информацию и изменения конкретного коммита (в данном случае предыдущего HEAD~1).

## Что нашли команды log -S и blame:
* git log -S"def" — ищет коммиты, в которых добавлялось или удалялось указанное слово (def). В нашем коде функций не было, поэтому ничего не найдено.
* git blame — построчно показывает файл calc.py с указанием автора и хэша коммита для каждой строки кода.

## Различие между git restore и git restore --source:
* git restore - отменяет все незакоммиченные изменения в файле и возвращает его к состоянию последнего сделанного коммита (HEAD).
* git restore --source=... - временно извлекает состояние файла из любого указанного коммита в прошлом (например, HEAD~2), заменяя им текущую рабочую версию


## Различия между git revert и git reset --hard:
* git revert HEAD — создает новый коммит, отменяющий изменения ошибочного. Сам ошибочный коммит не пропадает из истории.
* git reset --hard — физически удаляет коммиты из истории, стирая их навсегда.

## Почему в опубликованной истории безопаснее использовать revert:
Если репозиторием пользуются другие разработчики, git reset сломает общую историю и вызовет конфликты при синхронизации. Команда git revert безопасна, так как она просто добавляет новый коммит отмены поверх старых изменений, не ломая чужую работу.

## Различие между tag и branch:
* Ветка (branch) — это подвижная ссылка, которая автоматически перемещается вперёд при создании новых коммитов. Она используется для постоянной разработки.
* Тег (tag) — это статичная («замороженная») метка на конкретный коммит. Она никуда не двигается при создании новых коммитов и используется для фиксации стабильных версий проекта (например, релиз v1.0).
